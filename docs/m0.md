# M0: Realtime WebSocket Server Shell

## Objective

Deliver a small Go server library that accepts a stock OpenAI Realtime WebSocket client and delegates behavior to an application-defined `realtime.Service`.

M0 proves the server-shell architecture. It does not implement a model, agent, voice pipeline, or upstream proxy.

## Acceptance scenario

1. A test application registers a deterministic in-memory Realtime service.
2. The server exposes `GET /v1/realtime`.
3. An official OpenAI JavaScript client connects using a custom endpoint and test credential.
4. The client creates a session and sends a text conversation item.
5. The application service receives typed events.
6. The service emits a streaming text response.
7. The official client observes the expected response lifecycle without custom protocol code.
8. Cancellation and graceful close pass black-box tests.

## Supported M0 profile

The exact GA event names and schemas must be captured from current official documentation and locked by fixtures before implementation. The initial behavioral categories are:

- session creation and update;
- conversation item creation;
- response creation and cancellation;
- streaming text output;
- function call arguments;
- function call output;
- errors;
- terminal response state.

Audio payloads may be represented in the type system during M0, but end-to-end audio processing is not an M0 acceptance requirement.

## Work packages

### 1. Protocol inventory

- Record the current client and server event schemas.
- Separate required fields, optional fields, and tolerated unknown fields.
- Define the M0 compatibility profile.

### 2. Types and codec

- Define discriminated Go event types.
- Decode client events without losing unknown fields.
- Validate application-emitted server events.
- Serialize protocol errors consistently.

### 3. Transport

- Implement WebSocket upgrade and lifecycle.
- Add bounded read and write loops.
- Propagate cancellation and close causes.
- Define origin and authentication hooks.

### 4. Application interface

- Stabilize `Service.Open`.
- Stabilize the per-session input and output contract.
- Provide test helpers and a deterministic echo service.

### 5. Conformance

- Add golden JSON fixtures.
- Add malformed-event tests.
- Add ordering, cancellation, and backpressure tests.
- Drive the server through a stock official JavaScript SDK.

## Exit criteria

- `go test ./...` passes.
- Race tests pass for the session and transport packages.
- The official-client black-box scenario passes in CI.
- The supported event matrix is documented.
- Unsupported behavior is explicitly documented.
- No application package is imported by the shell.
